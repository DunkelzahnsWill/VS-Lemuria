# A Fire cast at a block that takes the flame and stays cold is free (G15)

**Done.** `TryIgnite` in `Lemuria/Evocations/Effects.cs` now asks, after handing a block the flame, whether it caught;
a block that took the flame and stayed cold, such as a loaded bloomery with no chimney, answers "not now", so the
cast fizzles and costs nothing, by hand or from a Fire Focus. Two of the game's blocks answer misleadingly and are
asked directly, as the old audit's diary found: a firepit, which only smoulders until its next tick, counts as
caught, and a pile on the ground is judged by whether it burns, so a cast at a pile already burning is a miss too.
`Effects.Light`, the Control Shelf's firestarter, now uses the same test (it asked the same question already). The
old audit's two tests, never run until now, are in: `misfire` (first boot) and `burningpile` (after the restart).
Both pass with the fix and both fail on the old code; the shelf's `lights` test still passes.

**Why.** Feature 6's brief, point 3, "A miss is free", names this case, and the owner's merge of it is also the owner's
word on that reading (R7), so the PR waits for the owner's merge, not for an inquisitor's "in".

**Why not another way.** A list of the known misfires would keep charging for another mod's block that stays cold; the
general re-ask errs, with a block that catches late, in the player's favour. It is what the shelf already did.

**Also.** The review thread will record the containers a machine reaches inside a claim as G61, mine, naming step 1,
apart from G58, the fire; my entry of 18:34Z gave both to G58.
